### Note: Code Version to Use

This is the latest version of the code, which is used to run Qwen 3 (4B) and Gemma 4 (E2B) Instruct experiments. Unless the purpose is strict reproducibility, starting from this branch is recommended. If strict reproducibility of experimental results is desired, especially for Qwen 2.5 (3B) Instruct, Llama 3.1 (8B) Instruct and Llama 3.2 (3B) Instruct, refer to branch ```reproducibility```.

### Files Used

The repository has 8 core files which are used for running experiments and analyzing results. The files, with the first 7 arranged in execution order, are as follows:

1. **prepare_datasets.py**: Downloads all datasets and converts the dataset into a consistent format for subsequent preprocessing and training.

2. **preprocess_dataset.py**: Converts the questions into the train and test set to a form that can be read by the LLM for both RL training and evaluation, i.e. add the chat template and format the questions according to a consistent prompt format.

3. **rl_confidence_calibration.py**: The main reinforcement learning (RL) step, used to train large language models. Upon request, the output can optionally be uploaded to wandb.

4. **evaluate_model.py**: Evaluates the RL model using the test set. Also supports evaluating zero-shot base models. Outputs a results file that can be used to analyze the results.

5. **evaluate_abstention.py** (optional): Uses an LLM judge to evaluate if the model has abstained from answering the questions. This file reads from the results output of evaluate_model.py, which contains the LLM responses to each question, therefore, evaluate_model.py must be run first.

6. **analyze_model.py**: Based on a results file generated by evaluate_model.py and if found, evaluate_abstention.py, outputs statistics detailing the accuracy and the confidence calibration ability of the LLM, and stores the statistics in a JSON file.

7. **format_results.py**: Formats the JSON file into a CSV file for summarized data retrieval and analysis.

8. **utils.py**: This file is a utilities file to reduce duplication of code between files.

### Code Requirements 

Software requirements: The libraries used for the experiment can be found on requirements.txt. 

Hardware requirements: One NVIDIA Ampere to Blackwell GPU. Highly recommended: CUDA NVCC version at least 12.0 - otherwise, some vLLM command line parameters need to be disabled. Code is expected to be able to run on H100 94 GB for Gemma 4 (E2B) Instruct, and a 3g.47g instance of H100 for Qwen 3 (4B) Instruct, and may run on even lesser VRAM depending on the configuration and hyperparameters.

### Code Reproduction Steps

To reproduce the results in the main experiments, follow the steps shown below:

1. Install the relevant libraries using ```requirements.txt```. We used miniforge to install the Python environment and pip to install the Python packages, but uv and pyenv are expected to work (not tested). 

2. Run ```prepare_datasets.py``` to download the dataset files and split the dataset into train and test sets. Simply call ```python prepare_datasets.py```.

3. Run ```preprocess_dataset.py``` to format the questions as a prompt, and then format the prompt according to the chat template. Thinking is disabled by default if the parameter is not provided. 

Example usage:
```
python preprocess_dataset.py --llm qwen3-4b --dataset deepmath-103k
```

4. Run ```rl_confidence_calibration.py``` to calibrate the LLM in confidence calibration. This step can take several days to complete. The configuration file is read from the specific file in ```config/rl```. Note that the command line argument does not include ```.yaml```. 

Example usage:
```
CUDA_VISIBLE_DEVICES=0 python rl_confidence_calibration.py --config_yaml qwen3-4b_deepmath-103k_brier-1
```

5. Run ```evaluate_model.py``` to evaluate the model in different settings. The configuration file is read from the specific file in ```config/eval```. Note that the command line argument does not include ```.yaml```. 

Example usage:
```
CUDA_VISIBLE_DEVICES=0 python evaluate_model.py --eval_yaml qwen3-4b_deepmath-103k_brier-1
```

6. (Optional) Run ```evaluate_abstention.py``` to determine whether the LLM has abstained from answering the model in different settings. The configuration file corresponding to ```eval_yaml``` is read from the specific file in ```config/eval```. The configuration file corresponding to ```judge_yaml``` is read from the specific file in ```config/judge```. Note that both command line arguments do not include ```.yaml```. 

Example usage:
```
CUDA_VISIBLE_DEVICES=0 python evaluate_model.py --eval_yaml qwen3-4b_deepmath-103k_brier-1 --judge_yaml gpt-oss-20b
```

7. Run ```analyze_model.py``` to view results.

Example usage:
```
python analyze_model.py --dataset_name bigmath --llm qwen2.5-3b --confidence_analysis  --use_model rl --reward_scheme brier-1 --run_suffix xml &> analyze_logs/bigmath_qwen2.5-3b_brier-1_llm-confidence-and-analysis_xml_results.txt &
```

8. (Optional) Run ```format_results.py``` to present results in a CSV table

### Configuration Directories

For easier management, the configuration is stored in the ```config``` folder.

**config/rl** stores the sets of configurations used for reinforcement learning (RL) training. A file in this directory, which you can specify, will be read by ```rl_confidence_calibration.py``` as the RL training configuration. The subfolder ```config/rl/template``` can be used to store configuration file templates. These templates contain all the parameters in the configuration file required to run the RL training except the reward scheme. The reward scheme will automatically be added when running ```create_config_rl.py```, which creates one config file in ```config/rl``` for every reward scheme. 

**config/eval** stores the sets of configurations used for RL evaluation. A file in this directory, which you can specify, will be read by ```evaluate_model.py```, ```evaluate_abstention.py``` and ```analyze_model.py``` as the evaluation parameters. The subfolder ```config/eval/template``` can be used to store configuration file templates. These templates contain all the parameters in the configuration file required to run the RL evaluation except the reward scheme and whether the base model is used. Configuration files corresponding to each reward scheme and the base model will automatically be added when running ```create_config_eval.py```, which creates one config file in ```config/rl``` for every reward scheme or the base model. 

**config/judge** stores the sets of configurations used for LLM judging. It will be read by ```evaluate_abstention.py``` and ```analyze_model.py```. 

There are convenience files prepared for you to automatically replicate configuration files across all reward schemes tested (including the base model during evaluation) while keeping the parameters irrelevant to the reward scheme or the base model unchanged. They will error out if one or more of the compulsory parameters are missing, helping you check for missing parameters.

**create_config_rl.py** takes a ```yaml``` file from ```config/rl/template```, replicates it by inserting all reward schemes examined while keeping all other parameters the same, and places the generated ```.yaml``` files in ```config/rl``` directory.

**create_config_eval.py** takes a ```yaml``` file from ```config/eval/template```, replicates it by inserting all reward schemes examined while keeping all other parameters the same, and places the generated ```.yaml``` files in ```config/eval``` directory.

For easy reference, the configuration files in ```config/rl```, ```config/judge``` and ```config/eval``` and the template files in ```config/rl/template``` and ```config/eval/template``` which are used for the experiments are placed in the ```config``` folder of the repository. 


### Output Directories

The datasets are stored in the ```datasets``` folder.

**datasets/train** contains the raw questions, the corresponding ground truth answers and the corresponding difficulty in the training set of each dataset

**datasets/test** contains the raw questions, the corresponding ground truth answers and the corresponding difficulty in the test set of each dataset

**datasets/rl-train**` contains the properly formatted prompt, the corresponding answer and the difficulty level of each question in the training set of each dataset, to be used during the RL stage. The properly formatted prompts are questions in the ```datasets/train``` folder reformatted as prompts which can be directly fed into the LLM during the RL stage. There are two layers of subfolders. The first subfolder represents the LLM, while the second folder represents whether thinking mode is enabled. For example, ```datasets/rl-train/gemma4-e2b-it/nothink``` folder contains the RL training dataset corresponding to prompts formatted to Gemma 4 (E2B) Instruct prompt chat template and with thinking disabled.

Note: For our experiments, thinking mode is always disabled.


The models are stored in the **models** folder.

**models/evaluate** contains the json files that contain question-level statistics on whether the response is correct and the corresponding confidence level. This json file is used to calculate the overall statistics in ```analyze_model.py```. There are two subfolders, namely ```abstain``` and ```final_answers```. ```abstain``` has one more subfolder layer, which denotes the LLM judge. Once past that layer, the ```.json``` files contain the LLM abstention judge verdicts on whether the LLM has abstained from answering the question. ```final_answers``` contains the list of answers the LLM model has output for each question in the test set. ```evaluate_abstention.py``` will read the file from the ```final_answers``` directory for the list of answers.

**models/results** contains the json files that contain the overall performance statistics of each model. These files provide more statistics than provided in the paper. The full results, in .csv format, can be obtained by simply running ```python format_results.py```.

**models/rl** contains the trained model checkpoints during the RL stage, i.e. the main training for confidence calibration.
